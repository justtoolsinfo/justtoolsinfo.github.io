How to test a responsive design

  1. 1

    Enter the address

    Type the page’s address — example.com, or localhost:3000 for a site on your computer — and press Test.

  2. 2

    Choose the screens

    Tick the phones, tablets and desktops you want, or add your own size such as 390x844.

  3. 3

    Compare the layouts

    Scroll and click inside each frame. Use the rotate button to check landscape.

  4. 4

    Zoom

    Keep Fit to see everything at once, or pick 50% or 100% to look closely.

Why some sites stay blank

A site can tell browsers not to display it inside another page, using the X-Frame-Options header or a frame-ancestors rule in its Content Security Policy. Google, Facebook, banks and many others do this to prevent clickjacking, and no in-browser tester can get around it.

Your own site usually has no such rule, so it works. If yours does, test a staging copy without the header, or run the site locally and enter its localhost address.

What this test shows — and what it does not

  • It shows how the layout responds to width and height: media queries, flexbox and grid changes, hidden menus, overflowing text and images.
  • It does not emulate touch input, the device’s pixel density, or a mobile browser’s user agent — the page is still drawn by the browser you are using.
  • For the last word on a real phone — Safari’s toolbar, the notch, keyboard behaviour — check on the device itself.
  • An http address cannot be shown inside this https page, except localhost. Use the https address.

FAQ

Questions about Responsive Design Tester

Where does Responsive Design Tester run?

Responsive Design Tester has to reach the network for a public lookup. The page says what leaves your device. Toolspire does not keep a copy of the query.

How do I test if my website is responsive?

Enter its address, press Test, and look at it on a phone, a tablet and a laptop side by side. Check that nothing overflows sideways, text stays readable and menus remain usable at every width.

Can I test a site running on localhost?

Yes. Type localhost:3000 (or whichever port your dev server uses). Browsers allow a local page inside a secure page, so it works without any setup.

Why is the frame blank or says “refused to connect”?

The site forbids being shown inside other pages with X-Frame-Options or a Content Security Policy. Many large sites do. Test your own site, a staging copy or a local build instead.

What screen sizes should I test?

At least a small phone (360–390 px), a tablet (768 px), a laptop (1366 px) and a large desktop (1920 px). Then drag in any width where your design has a breakpoint.

Is this the same as a real phone?

For layout, yes — the frame is a true viewport of that size. It does not reproduce touch, pixel density or a different browser engine, so finish with a check on a real device.

What are the Tailwind breakpoints?

sm 640 px, md 768 px, lg 1024 px, xl 1280 px and 2xl 1536 px. Each applies from that width upwards.

Is the address I enter sent to you?

No. Your browser loads the page directly from its own site, as if you had opened it in a tab. The address is remembered only in this tab so it is there next time.
